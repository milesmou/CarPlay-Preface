## 蓝牙：音乐链路确实没有恢复

- 236–291 行：17:03:09.362 应用记录将蓝牙音乐交给 CarPlay；A2DP 从 2 → 3 → 0，AVRCP 也从 2 → 0。
- 477–479 行：切到蓝牙输出后不再提供 CarPlay 音频，但 A2DP/AVRCP 仍为 0，HFP 为 2。
- 586–603 行：蓝牙模式建立会话，恢复音乐连接调用报 `NoSuchMethodException`。

这支持“CarPlay 音频撤下，但原车蓝牙音乐链路又未恢复”的解释，符合用户听到手机出声的现象。
HFP 已连接只说明电话 profile 状态，不能证明蓝牙音乐已连接。
异常只证明本应用对运行时代理反射查找失败，不能据此断言底层系统绝对没有 connect 实现，或确定是方法缺失还是隐藏 API 限制。

上轮新增的防护在主动 disconnect 前检查 connect 方法和返回类型，能阻止这类可预见的单向交接；
它不能恢复构建 85 已经断开的链路，也不能证明蓝牙输出已在实车修复。
参考 OTA 的 `IA2dpExtension` 虽声明 `reqA2dpConnect`，缓存中的 `BtExtension.getA2dpExtension()` 返回 null，
不据此添加未经确认的私有恢复路径。

目前只能确认按键转发和去重有效，不能确认原车处理被独占，也没有证据声称本轮已解决跳页。
