# 构建 100：授权组件蓝牙交接生效，媒体助手仍被拒绝

2026-10-20，分析用户提供的 E 盘应用诊断、车机日志和 APK。实际设备为 **IHU353G / Android 9 API 28 / 系统 169**，主应用 **0.1.1 / 100**。用户反馈 CarPlay 音频已能正常切歌。本轮只分析和更新记录，没有修改运行代码、构建、签名、安装或运行单元测试。

## 结论

**已确认生效的是授权组件 10 的会话 A2DP 断开／恢复，独立媒体助手 1 没有取得媒体中心准入。** 两个组件不能混为一项成功结果。

媒体助手已安装并实际运行，日志显示 `systemApp=false; mediaPermission=true`，但 OpenAPI 明确拒绝它自己的 `mediacenter` 授权；助手返回 `SDK onAPIReady=false`、`registration token present=false`。主应用的媒体中心授权也仍被拒绝。因此这次切歌成功不能归因于助手注册了原厂音源，也不能归因于 QQ 授权已获准。

与构建 99 不同，本次授权组件实际断开了所选 iPhone 的 A2DP／AVRCP，主应用确认后才取得音乐焦点。14:51:31 的方向盘下一曲来自本应用 `preface-intercept`，成功发送一次 CarPlay NEXT，广播回声被去重。原厂媒体中心仍收到了同一按键，但此次对应时间段没有检索到上一轮的蓝牙 `onSkipToNext`、AVRCP PAUSE 或蓝牙焦点申请链路。这支持“蓝牙交接消除了本次播放争抢”是改善原因；不是通过卸载助手的对照试验得出的唯一因果结论。
