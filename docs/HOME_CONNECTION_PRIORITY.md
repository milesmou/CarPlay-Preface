# 首页设备列表与 USB 优先级

2026-10-16，0.1.1 开发版。按用户要求简化首页：设置放到右上角操作区首位，左侧显示实际连接车机蓝牙的手机，点击设备发起无线 CarPlay；右侧显示 USB 自动连接状态与说明，不再提供 USB 连接按钮或重复设置入口。

## 设备列表

`ConnectedBluetoothPhones` 在页面可见期间读取蓝牙接收端 A2DP sink（11）、HFP client（16）及可用的普通 Android profile，并观察 ACL 连接／断开广播。已配对列表只用于查询设备的实时 `isConnected()`；没有连接证据时不显示为“已连接”，接口不可用也不推断已连接。已明确的非手机设备类型排除，未提供类型的设备允许显示；名称不用于判断是不是手机。

列表按地址去重、按名称排序。断开广播可以清除尚未更新的 profile 快照；关闭蓝牙、权限失效或离开页面时清理观察状态与 profile proxy。主页轮询只刷新状态，不执行扫描、配对或主动建立蓝牙连接。Android 12+ 未授权时显示“附近的设备”入口；按用户后续要求移除主页“打开蓝牙”按钮，无设备时仅显示连接提示。

设备点击前再次刷新连接状态，保存用户点击的手机，再启动现有无线流程；同一手机的有效无线会话直接返回。以前的蓝牙自动连接设置仍尊重用户保存的选择，默认不开启；即使用户开启，USB 优先级同样生效。

## USB 自动连接

- 原有 Manifest Apple USB 插入入口继续处理进程未运行的场景，保留系统 USB／VPN 授权；启动过滤不再因 CH341 配件而打开 CarPlay，MFi 内部的 CH341 检测与授权保留。
- 进程内 `UsbAutoConnect` 接收 USB 插入事件；首页也核对当前设备，支持先插线、后打开应用。只匹配现有 iPhone USB matcher 使用的 Apple VID，不把其他 USB 配件用于自动连接。
- 同一设备节点的重复观察不会反复拉起。拒绝授权或启动失败后不靠首页轮询循环重试；物理重新插拔可开始新尝试，原页面手动重试保留。配置切换导致的重新枚举继续由原 USB 控制器处理，不因为每个插入通知都重建有效会话。
- USB 新接入、正在启动或会话有效时阻止主页无线点击、蓝牙唤醒、开屏自动连接及迟到的通知权限／连接清理回调改回无线。USB 到达后的新请求代际会使之前的无线启动失效；正式打开投影前再次核对当前 USB 优先状态。
- 已运行无线时，USB 插入会切换到有线；旧连接仍通过现有清理屏障退出后再启动新连接。新主机页面也检查旧会话的真实连接方式，不把无线控制器当作 USB 会话接管。已停止重试的 USB 页面收到重新插入事件时允许新尝试。
- USB 拔除后可以点击蓝牙设备发起无线连接；没有增加自动回退或擅自选择另一部手机。

## USB 失败后手动选择无线（2026-10-16 修正）

用户报告 USB 连接失败后返回首页，点击无线设备仍走 USB。根因是主页按钮、连接入口、最终投影 Intent 和主机启动检查均仅用物理 USB 存在判断优先级；VPN 组件缺失等失败没有释放用户选择无线的入口。

`UsbAutoConnect` 现在区分物理接入、当前有线尝试失败，以及用户为这次接入明确选择无线三种状态。VPN 拒绝／组件异常、控制器连接失败及启动 Activity 异常会记录对应尝试的失败；首页手机按钮仅在无 USB 优先或失败后无有效有线会话时允许选择无线。只记录失败不会自动回退，首页轮询和蓝牙唤醒仍保留 USB 优先。

用户点击已连接手机后，当前这次 USB 接入让出优先级；旧控制器按现有清理屏障退出，再启动普通无线流程。最终 Intent 不再携带 USB action 或 device。主页轮询、主机启动复核及蓝牙接入统一读取当前优先状态，旧 USB 授权回调及排队启动通过请求代际失效，不会覆盖该选择。没有控制器的初始 VPN 失败也允许直接手选无线。

选择只保留在本进程和当前 USB 接入内。重复观察同一接入不抢回；重新插拔、不同 USB 设备或手动有线重试恢复正常 USB 优先。有线重试清除旧失败状态，迟到的失败回调不能标记新的尝试；有效有线会话保持优先。

定向回归：`UsbConnectionPriorityTest`、`HomeTransportSwitchTest`、`CarPlayVpnConsentTest`、`PhoneBluetoothReceiverTest`、`WirelessStartupRecoveryTest` 共 **91 项通过**（含 SDK 参数化执行，重复运行不累计）。覆盖插线状态下失败转无线、初始 VPN 失败、旧 USB 清理等待、延迟授权、有效有线会话、重复接入通知及重新插拔抢占。未构建或安装新 APK，未运行全量 CI，实车切换结果待验证。应用版本仍为 0.1.1 / 85。

`startActivity()` 返回只代表系统接受了调用，不能证明车机已显示页面或 CarPlay 已建立。系统授权仍由用户决定，系统缺少对应组件时仍按 USB/VPN 方案明确失败。
