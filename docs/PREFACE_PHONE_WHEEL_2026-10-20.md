## 当前行为

| 状态／入口 | 行为 |
| --- | --- |
| 当前 CarPlay 单路来电 | 电话键 299／事件 200005 的短按发送一次 Telephony Hook Switch。 |
| 当前单路活动／保持通话或拨号 | 同一电话键短按发送一次 Telephony Drop。 |
| 标准窗口键 5／6 | 5 仅在来电时接听；6 挂断或拒接。物理／窗口 DOWN-UP 配对处理，不把重复按下当成多次操作。 |
| HFP 已连接、连接中或断开中 | 保留原车电话处理，本应用不再向 iPhone 双发命令；不改变 HFP／SCO、配对、音源或蓝牙开关。 |
| HFP 查询失败或状态未知 | 保留原车，不将查询失败当成没有蓝牙通话链路。 |
| 蓝牙关闭、没有蓝牙能力或明确 HFP 已断开 | 由 CarPlay 命令处理；不为使用电话键自动连接或开启蓝牙。 |
| 无会话、无可识别通话、未知通话状态或多路／等待通话 | 不发出无目标的 Hook／Drop，保留原车或手机界面操作。 |

两种音频方案均注册电话入口，不依赖音乐播放、音乐焦点、媒体中心准入或无障碍服务。没有新增设置或系统授权。已有可选方控服务和前台窗口也接入相同处理器。

## 去重、来源与生命周期

电话广播只接受既定 action、事件类型 200005 和短按 action=0。长按 action=1 不发送电话命令，并取消当前窗口的短按候选；窗口重复按下、系统长按标志、超过 Android 长按时间的释放和取消事件也不执行短按。长按拒接、多路接听／保持切换未擅自定义。

广播与窗口共用 800 ms、同一通话 token 的回声去重，跨来电→活动状态也继续生效，避免接听后的迟到广播误变为挂断。只有命令成功入队才记去重，失败允许重新按键。长按、空闲或失效事件不恢复旧命令。

RCALL 为非保护的普通广播，因此动态注册要求发送方持有平台 `android.permission.INJECT_EVENTS`；本应用不申请或授予该权限。注册成功不证明实际事件已到达。处理器不调用 abortBroadcast，也不声明输入观察者可以独占电话键。原车 HFP 存在时不双发；原厂电话页面是否仍跳转需实车核对，本次不声称已阻止原车页面。

实际发送前再次核对当前处理器、控制器、活动 AirPlay 会话、同一通话 token／阶段及 HFP 归属。原车先接听、通话结束／替换、多路通话、HFP 重新连接、取消、断开或关闭都会使排队命令失效。控制器替换活动 AirPlay 会话、会话结束或退出时清除自己的通话状态；旧接收器关闭后不能影响重连。日志区分 queued、reportWritten 和尚未确认的手机结果，不记录通话身份。
