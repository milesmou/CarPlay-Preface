# 方控按键学习与处理状态

2026-10-15，应用实现变更，适用目标为星瑞 E02。借鉴用户所提供 GeelyPlay APK 的学习／停用和分层状态设计，未引入其桥接组件或反编译实现。APK 来源校验及代码证据见 GeelyPlay 静态分析（分析文档已清理）。

## 按键学习

设置 → 车辆 → 方控按键，提供上一曲、下一曲、Siri 三个操作的“学习按键／恢复默认／停用应用转发”。默认代码为 88／87／231，物理 304／305 与标准 88／87、语音 298／219 与 231 分别作为同一按键处理。按用户要求，仅保留新映射；旧版独立 Siri 开关、自定义角色和窗口学习路径已删除，不再读取或迁移旧 `siri_key`／`key_SIRI` 值。旧按键值留在设备存储中也不能覆盖新默认或重新启用已停用的 Siri。

学习在本页主动发起，10 秒超时；页面退出、通话、取消时结束。只保存键码，不保存设备名称、标识或输入文字；电话、音量、系统、文字输入键拒绝分配。重复绑定或与启用中的摇杆／缩放角色冲突时拒绝保存。学习完成的当前按键和短时跨来源回声不再触发媒体操作。新配置立即用于应用后续收到的按键，不重连 CarPlay。

接入已有前台、媒体广播、可用的原厂输入观察接口；已启用的方控服务也能传递事件。不会自动申请无障碍权限。原厂观察接口仅申请已知媒体键及已经保存的自定义键，不扫描未知私有键；无法送达应用的键不能保证学习。标准媒体语义回调不包含原始自定义键码，直接执行同名动作，不再反查物理键映射；仍尊重动作停用及统一的会话、通话、蓝牙和归属检查。原车语音广播保留 Siri 语义，仅在其绑定仍指向 Siri 时触发；跨类型改键需要原始 KeyEvent 或观察回调。

停用只阻止本应用转发，不能阻止原车在其他进程的动作。原车蓝牙方案仍由原车处理媒体键，学习配置不会使应用再次转发媒体键；Siri 保留独立检查。通话、媒体归属、会话及焦点检查继续保留。无障碍服务只将 Siri 交给同一新处理器，不维护第二套 Siri 配置或请求；可选摇杆配置继续独立保留，学习摇杆键时也会拒绝占用新媒体／Siri 映射。自定义 Siri 键可显示同一方控服务的设置入口，不自动申请授权。

## 处理状态

同一页面每秒刷新输入申请状态、当前观察注册收到的回调次数、原厂媒体音源注册／播放归属。计数为回调次数，包含按下与释放，不能当成切歌次数。每次重新申请归零；旧注册已排队的回调不能改变新注册的计数。

独占处理始终显示“未确认”。`requestKeysInterception` 返回成功、收到观察事件、原厂音源获准播放是三个独立事实，均不足以确认原车停止处理。不能凭此页面宣称已修复切歌跳回原车媒体页。

固件依据仍为 IHU519G / FS11A1 / Android 9 / 构建 327，OTA SHA-256 为 `f61a7399d61a7f4502b9289ea6c49c661c39c459aae81e676722bcf9be913c01`。接口证据和本地缓存定位见 [固件方控分析](PREFACE_FIRMWARE_327.md)，并未新增固件独占能力证据。IHU353G 等实际报告设备与参考 OTA 的身份差异继续保留。
