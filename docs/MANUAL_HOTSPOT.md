# 手动车机热点与临时热点

## 2026-10-16：手动断开后的有效预约复用

用户进一步要求：手动断开再连接时，热点仍有效就复用，避免重新创建。构建 70 将本节之前的“断开即释放”和“只在原控制器内保留”规则扩展为应用进程内交接：主动断开 CarPlay 或重建连接时，先清理旧控制链路、监听与音视频会话，保留仍有效的本应用 LocalOnlyHotspot 预约及实际配置；旧控制器不再拥有它。下一控制器取得预约后，重新验证系统状态、接口和原地址，有效才使用原名称、密码及实际频段／信道，失效则释放并申请新预约。既不接管系统／其他应用的热点，也不根据旧凭据假定热点仍有效。

空闲预约移除旧控制器的诊断回调，避免持有旧 Activity；新的连接重新接入自己的诊断。手动断开不保留旧会话或自动重试，也不继续显示“连接运行中”的前台通知。预约只在本进程存活期间保留，系统停止热点或进程被回收后不保证热点继续存在。

完全退出、移除运行任务、明确重置临时热点，以及下一次实际启动 USB 或手动热点连接时释放空闲预约；手动车机热点仍不自动关闭。退出期间旧资源清理屏障继续保留，不能靠转交预约提前放行未清理的 socket。

构建与定向验证结果见 [主动断开复核记录](DISCONNECT_RECONNECT_AUDIO_2026-10-16.md)。后面的 34 项验证及原生命周期描述属于此前实现的记录，不作为此扩展的实车验证。

无线连接方式列表首先显示“手动车机热点（推荐）”，随后显示“临时热点”。推荐标记不改变当前已保存的选择；未配置时仍默认使用临时热点。

## 2026-10-15：热点配置弹窗

按用户截图优化 `HotspotCredentialsDialog`：使用应用自己的标题、圆角输入框、颜色和按钮，避免 OEM AlertDialog 主题造成标题低对比度、输入框仅有下划线及底部文字按钮不清楚。名称／密码保留可见标签，密码默认隐藏，显示切换保留文本与光标选区；安全类型在表单内展开选择。说明改为简短的匹配提示，并明确保存后下次连接生效。

取消与保存固定在底部且等高，表单按可见窗口滚动。紧凑横屏空间足够宽时两字段并排，窄窗口继续上下排列；键盘缩小可见区域后重新计算高度，并将聚焦输入框滚入视口。尺寸和间距集中为命名 dp 常量，按钮复用 `DiPlayButton` 的形状规则。保留键盘 Next／Done 和隐藏键盘操作；Dialog 关闭或 Activity 销毁释放窗口监听。

验证、SSID／密码空白精确保留、OPEN 与 WPA2／WPA3 选择、未保存取消、私有持久化和标记下次重连的规则保持原样，没有修改系统热点名称／密码或中断当前会话。活动页只将已验证提交交给原保存回调。

21 项定向测试通过（弹窗 11、热点设置 9、翻译 1）。1920×720 横屏、字体 150% 已核对全窗口、高密度、窄可用窗口、深浅色、Arabic RTL 和键盘可见区域约束截图，保存在忽略目录 `agent_docs/screenshots/hotspot-dialog/1920x720-*-font150.png`。键盘用可见区域缩小模拟，实际车机输入法仍需新包验证。没有构建 APK，现有 0.1.1-64 不含此次弹窗优化。

## 连接方式与生命周期

2026-10-14 按用户要求增加无线热点二选一，界面入口仅放在“设置 → 连接”。2026-10-15 按后续截图要求合并到“无线连接”卡片，删除独立的“热点手动配置”卡片，并移除该卡片内的“开启车机热点”“打开车机热点设置”两个按钮。默认继续使用临时热点；选择手动模式后，在同一无线连接卡片内提供 SSID／密码配置，填写车机系统中实际开启的热点信息。选择手动方式后的热点开启尝试、进度及权限提示保持现有行为。保存后在下一次连接生效，当前会话保持运行，首页不增加配置模块。密码只保存在应用私有设置，不进入设置导出或诊断状态描述。

手动连接通过 ManualHotspotManager 观察已运行热点接口，优先使用系统可读取的热点归属，排除未就绪接口、已知 Wi-Fi 上游和无归属证据的默认网络；回退只接受唯一的无线非上游候选，不使用 USB 或 Wi-Fi Direct 网卡。连续稳定观察后才发布端点，发布前再次核对接口和地址；不明确或歧义时报告未就绪。读取热点配置获准时核对 SSID；读取受限时不能验证保存密码是否正确，需用户确保一致。热点状态／反射读取不可用不代表固件接口已验证。

应用仅持有本轮多播锁与观察回调，关闭手动模式连接时释放自身资源，不关闭系统热点。按用户新增要求，选择手动模式后调用已有 CarHotspotTethering 开启保存配置的热点；检查 WRITE_SETTINGS、接口和实际热点状态，复用已经授权的本地 ADB 回退，不自动申请 ADB 授权。失败显示权限、接口或开启失败原因；可从应用请求修改系统设置权限后重试。此权限不保证厂商系统接口获准。存在 CarPlay 会话时跳过开启，切换到临时模式或页面停止时取消待处理任务。临时模式仍使用 LocalOnlyHotspot 预约，断开时释放本应用预约。两种模式共用 iAP2 凭据公告和 AirPlay 监听，切换不会自动回退为另一种模式。

此实现不增加车型分支。参考 OTA 为 IHU519G/FS11A1 构建 327，来源 SHA-256 为 `f61a7399d61a7f4502b9289ea6c49c661c39c459aae81e676722bcf9be913c01`，静态热点接口名与服务证据见 [固件参考](PREFACE_FIRMWARE_REFERENCE.md) 和 [事实索引](firmware/ihu519g-327.json)。用户先前报告的 IHU353G 与参考固件身份不同；本次普通 Android 接口实现、模拟截图和单元测试都不证明任一固件已完成实车验收。

待实车验证：系统热点在应用 UID 下的状态和接口归属可读性、SSID/密码匹配、蓝牙凭据传递、iPhone 自动／手动加入、首个 AirPlay TCP、画面／音频与重新连接。暂未构建或安装 APK。

界面截图固定为 1920×720 横屏：常规密度与高密度／窄 dp 窗口均保持同一像素尺寸，字体比例 150%。本地截图目录为 `agent_docs/screenshots/manual-hotspot/`；主车机截图 `head-unit-1920x720-wireless-font150.png`、`head-unit-1920x720-manual-font150.png`，高密度截图 `high-density-1920x720-wireless-font150.png`、`high-density-1920x720-manual-font150.png`。使用已存在的设置行样式及对齐，高密度时新控件按文字内容增高以避免裁字，首页控件不采用这项改动。

定向验证共 36 项通过：ManualHotspotReadinessTest 19 项、ManualHotspotConfigTest 5 项、ManualHotspotValidationTest 3 项、WirelessHotspotSettingsTest 6 项、WirelessHotspotModeSelectionTest 2 项、HostConnectionSettingsRefreshTest 1 项。覆盖两种管理器互斥选择、接口稳定／歧义／取消、凭据验证和精确保留、导出不含密码、已有会话不中断及下一次握手读取新设置。未执行全量 CI、Lint 或 APK 构建，不能替代真车验证。

## 首次接入失败保留临时热点（2026-10-14）

17:50 第五份报告补充：无线启动期间窗口 1760×720 → 1920×720 触发完整重启，系统已回调但仍在观察信道的热点预约未被即时关闭，下一次创建报 generic error。工程现在保留无旋转／布局设置变化的无线启动控制器及画布，适配新窗口，下次连接按新尺寸协商；明确关闭时也立即释放尚在准备的预约，并防止迟到失败清理重复关闭。完整替代连接等待旧控制器实际释放后才开始，退出／线程中断可取消等待。用户确认首次自动接入成功、第二次手动点击连接；这说明间歇性失败，尚不能保证这些生命周期修正解决全部自动加入问题。具体证据见 [第五份报告](CONNECTION_REPORT_2026-10-14.md)。

用户指出临时热点已创建但接入失败时反复创建新热点。原路径在首个 AirPlay TCP 超时后释放完整无线栈，页面随后重建控制器，又向 Android 申请新预约。现拆分启动失败清理与断开清理：首次会话尚未建立时保留有效 LocalOnlyHotspot 预约及其实际配置，清理蓝牙 bootstrap、Bonjour 和本轮 AirPlay 监听；重试仍由同一控制器拥有该预约和 MFi provider，不转移到全局缓存。

自动重试、现有“重试连接”按钮和无设置变化的菜单返回恢复优先走此路径。每轮在后台调用 `validateReady()` 检查预约、接口及原地址；有效则复用原名称、密码和系统配置，已停止／接口或地址失效才释放并重新创建。慢速 Bonjour 清理不会阻塞 UI 的重试申请，排队重复申请和旧 generation 清理不能启动额外尝试或关闭新资源。断开、退出、切换连接方式及用户应用需要完整重连的设置仍按连接生命周期释放本应用预约；已建立过的会话不走这条首次启动重试路径，运行中的会话不因排队启动重试被中断。

保留热点的通用控制通道错误也使用现有最多五次自动启动重试预算，不无限循环。次数用尽显示手动重试按钮，预约保留至明确断开；控制链路和监听已清理，此时手动加入 Wi-Fi 后仍须点击重试连接。日志记录预约保留、复用或失效重建的动作，不记录网络凭据，不猜测未知信道。手动车机热点的开启／关闭规则不变。

本轮定向测试 34 项通过（common 21、shared 13），覆盖连续启动失败只创建一次、有效配置精确保留、失效替换、退出释放一次、旧清理与重复重试隔离、慢清理不阻塞、页面采用同一控制器、次数上限及成功会话保护。未运行全量 CI、Lint，未生成新 APK。报告设备仍为 IHU353G，参考固件身份和 SHA-256 仍为上文的 IHU519G/FS11A1 构建 327；这是工程修正，没有新增固件接口或实车验收证据，不能据此保证 iPhone 自动加入成功。
