# 蓝牙触发无线重连复核（2026-10-16）

范围：星瑞 E02 应用连接流程；不新增车型分支或固件私有接口。参考资料为
`PREFACE_FIRMWARE_REFERENCE.md` 和 `firmware/ihu519g-327.json`，参考 OTA 是
IHU519G/FS11A1、Android 9、构建 327，SHA-256 为
`f61a7399d61a7f4502b9289ea6c49c661c39c459aae81e676722bcf9be913c01`。
此前用户报告设备为 IHU353G，不能把本次应用测试当作任一固件的实车验证。

## 完整流程与设备选择

1. 开启“iPhone 蓝牙连接时连接”后，接收 ACL_CONNECTED，以及接收端 A2DP Sink、AVRCP Controller、Headset Client 的 CONNECTED 广播。静态接收器提供进程唤醒入口；应用动态接收器补充运行时 profile 事件。
2. 使用已保存的 `phone_address` 匹配设备。这是无线选机时记住的 iPhone；用户主动选择另一台手机后，以新选择为准，不另外引入一份可能冲突的“最后成功设备”。其他手机、未连接状态、缺少蓝牙权限均跳过。
3. 若已有连接所有者，将事件交给该所有者判断。已有 USB、不同手机、活动 AirPlay 会话、正在停止、设置菜单或重建中均不替换连接。正在尝试连接时继续现有尝试。
4. 若同一手机的无线启动因可重试失败耗尽预算，新连接事件允许恢复一轮有上限的重试。优先调用现有控制器 `retryWirelessStartup()`，保留有效临时热点预约；无法复用时走原有受控清理与重建。配置、权限、Wi-Fi 手动恢复以及已判定蓝牙不可用等阻塞不据广播强行绕过。
5. 无所有者时启动 DiPlayActivity，携带匹配的手机地址与事件单调时钟时间。页面接受 60 秒内且仍匹配当前选择的请求；实际执行前和通知权限结果返回后再次校验选择、开关、页面生命周期和已有会话。蓝牙触发固定走无线，不受“打开应用时连接”的 USB 默认方式影响。
6. 主连接页面检查所需权限、认证资料，创建控制器。无线流程准备热点及可用接口、监听和 Bonjour，然后建立 RFCOMM/iAP2，完成认证和 Wi-Fi 参数交换，发送 StartSession 并等待 AirPlay。蓝牙音频连上不等于这些步骤完成。
7. 原有首次 TCP 超时与无线启动重试预算继续生效。临时热点重试使用同一有效预约；稳定视频达到既有阈值才重置预算。成功会话使旧的重试定时器失效，并解除旧“停止重试”状态，允许后续真正断线时正常恢复。

## 确认并修复的问题

| 问题 | 修正 |
| --- | --- |
| `hasSession()` 包含失败后保留的控制器，后续蓝牙成功事件被无条件挡住 | 区分连接所有者与活动会话，让原所有者恢复可重试的失败 |
| 15 秒防抖没有区分手机和本次开机，快速断开再连接也被挡住 | 防抖按手机和 boot count 隔离；所选手机 ACL_DISCONNECTED 清除计时，其他手机或 profile 断开不清除 |
| 页面启动期间更换手机、关闭自动连接或建立另一会话，旧请求仍可能继续 | 携带目标与时间，执行及权限回调时复核；拒绝请求不落入“打开时连接”路径；权限期间页面重建保存请求来源 |
| 旧代际的定时器会修改新代际的重试标记，普通错误的重试还可能重建刚连接的新会话 | 定时器票据与控制器代际双重校验；实际重试及重建撤销旧票据；比较排队时与执行时的会话 |
| 重试停止后迟到的成功握手仍留下停止标记，之后断线不能恢复 | 成功会话清除停止标记和旧排队任务，但不提前清零稳定视频预算 |

## 诊断与验证

`Phone Bluetooth wake` 报告可区分 `startActivity-returned`、`activity-received`、
`wireless-start-requested`、`wireless-retry-resumed`、`connection-in-progress`、
`session-active`、`requires-user-action`、`activity-request-cancelled` 等结果。
报告不输出手机地址或广播原始 extras。`startActivity-returned` 仅表示调用返回，
不是车机允许后台拉起页面的证据；后续阶段仍需结合连接日志检查。

定向测试覆盖：蓝牙事件匹配、API 28/29/33 接收、权限、跨手机和跨开机防抖、
快速断连、页面请求校验、USB 默认与无线唤醒隔离、已有会话保护、耗尽后恢复、
旧定时器、迟到成功、临时热点复用、失败清理及无线交接。不运行全量 CI。

结果：10 个测试类共 **94 项定向测试通过**。先运行连接链路回归，页面请求逻辑最后调整后，
再对受影响的页面启动／热点设置／默认连接测试回归，并单独复测最终版本的
`BluetoothAutoConnectActivityTest`（12 项，API 28/33）。XML 结果保存在本地忽略目录
`agent_docs/reviews/bluetooth-auto-reconnect-2026-10-16/`；未修改运行环境或执行完整 CI。

实车待验证：应用在后台或进程未启动时，所选 iPhone 蓝牙连接是否收到匹配事件并允许打开页面；
首次失败后再次连接蓝牙能否自动进入 CarPlay；连续离车／回车与蓝牙快速重连；
已运行 USB 或 CarPlay 时连接事件是否保持现有会话；手动热点和临时热点分别验证。
本次未构建或安装新 APK，也未作实车成功结论。
