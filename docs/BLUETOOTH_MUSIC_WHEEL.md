# 音频方案

当前测试包 0.1.1 / 95 已构建，内置授权组件 7，已覆盖安装到 API 34 模拟器 emulator-5558 并保留数据，未实车验证；[构建核验](ANDROID9_AUTHORIZATION_COMPONENTS.md)。位于“设置 → 音频”的第一个卡片，名称为“音频方案”，不再显示实验性标记。保留两个互斥选项：

| 选项 | 行为 |
| --- | --- |
| CarPlay 音频（默认） | 使用 CarPlay 音频和媒体方控，音量由原车调节。 |
| 蓝牙音频 | iPhone 音频走原车蓝牙，CarPlay 保留画面与触摸，媒体方控由原车处理。 |

移除“按播放状态调整媒体／导航音量”及第三种模式，删除前台窗口与后台按键服务的音量流切换路径。旧 diplay_navigation_wheel.enabled 保存值不再读取、迁移或恢复；它不能重新启用该功能，也不会单独触发后台服务恢复。媒体／导航默认流 3／12、独立路由设置，以及实际语音触发的 30% 导航混音不受影响。

## 保存与会话

两种模式只复用 car_bluetooth_audio，保留用户已保存的蓝牙选择；未开启时为 CarPlay 音频。保存后调用 markReconnectNeeded()，在下次连接生效，当前控制器、焦点和方控继续按现有会话运行，不擅自断开。

蓝牙模式关闭整套 CarPlay 音频协商，不只静音音乐：不公告音频格式、不接管主音频资源，拒绝普通及缓冲音频 SETUP，保留屏幕、触摸与数据。导航、电话和 Siri 的声音去向取决于手机与车机路由，异常时切回 CarPlay 音频。

蓝牙会话不创建音乐 MediaSession、不申请音乐焦点、不重复转发媒体键或申请原厂播放音源；保留同手机、通话、取消代际和真实播放状态检查。直接蓝牙连接接口不可用时可使用内置授权组件的限定代理，细节见 [蓝牙与方控修正](BLUETOOTH_WHEEL_RECOVERY_2026-10-19.md)。系统受理不等于已经连接，原厂自动暂停与切歌跳页仍需实车确认。
