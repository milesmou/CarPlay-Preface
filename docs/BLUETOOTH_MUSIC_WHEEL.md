# 音乐与方控方式（实验性）

2026-10-15，按用户要求完善实验性页面的原车蓝牙模式。用户确认原车蓝牙切歌不会打开原车多媒体页面；这是用户对原车路径的观察，并不代表与 CarPlay 同时运行后的混合路由已验证。

## 设置与生效时机

- 位置：设置 → 实验性 → 音乐与方控方式（实验性）。按用户后续要求，将蓝牙音频与方控音量联动两个开关合并为一个单选入口，提供三个互斥状态：CarPlay＋按播放状态调节音量（默认）、CarPlay＋保留原车音量、原车蓝牙＋音乐和方控。
- 复用既有 `car_bluetooth_audio` 与 `diplay_navigation_wheel.enabled` 保存值，不进行迁移或重置。已选蓝牙时显示蓝牙方案；否则按已保存的音量联动值显示相应 CarPlay 方案。蓝牙方案下原来的音量联动保存值不参与运行。
- 设置变更只持久化并调用 `markReconnectNeeded()`，由用户选择立即重连或下次连接。运行中的控制器以创建时的 `AirPlayConfig.disableAudioOutput` 为准，方控接入在首次 attach 时冻结该会话的音量联动值；同一控制器的页面恢复不会重读新保存值。保存选项不立即释放其方控、焦点或音频能力，也不恢复／重绑后台按键服务。
- 开启前需把 iPhone 连接到原车蓝牙音乐，并选中车机蓝牙音源。应用不修改配对、不自动连接／断开 A2DP/HFP，也不切换原车音源。

## 实际行为

复用现有“不给 iPhone 提供 CarPlay 音频”的协商方式：Bonjour 与 `/info` 使用同一组无音频能力，`/info` 不再公告音频格式和延迟，缓冲音乐也不启用。补上普通音频 SETUP 100/101/102 的拒绝路径，避免手机仍请求音频时建立重复的 CarPlay 输出；已有 103 缓冲音频拒绝逻辑继续使用。屏幕、触摸、数据通道继续保留。

此实现关闭的是整套 CarPlay 音频能力，不是仅把收到的音乐 PCM 静音。音乐预期由 iPhone 的原车蓝牙 A2DP 路由播放，媒体方控由原车 AVRCP 处理；导航、通话和 Siri 的声音路由也可能改变。开关说明明确提示这一范围及无声／手机外放时关闭。不同 iPhone 音频路由及 Siri 结果仍待实车核对，不保证所有声音自动选择原车。

蓝牙模式的会话不注册媒体广播／私有媒体按键观察者，不创建用于音乐的 Android MediaSession，不申请音乐焦点，不向 CarPlay 重复发送媒体按键，也不申请原厂媒体中心的播放音源。进程之前已创建的原厂注册可保留为空闲状态；不将“注册存在”当作播放源归属。

前台窗口和可选后台按键服务将标准媒体／音量键，以及参考 E02 固件已确认的 301/302/304/305 交回系统；后台服务不让这些键被自定义摇杆映射抢走。显式按键学习仍是用户操作，语音键与普通触摸保持原有处理。原车音量继续由原车控制。

诊断显示控制器实际的 `carBluetoothRoute`；启动采样复用接收端 A2DP sink／AVRCP controller／headset client 的状态日志，不再将手机端 A2DP source／headset 的查询当作车机连接状态，也不记录手机名称。状态查询失败或未连接不会被冒充为路由成功。

## 验证及边界

初版蓝牙模式 35 项定向测试通过（common 22、shared 13）：保存开关不停止当前会话且标记重连、已有会话不读取新保存值、蓝牙模式不申请音乐焦点或媒体源、不重复发送切歌、自定义后台映射交回媒体键，以及无音频协商时拒绝普通／缓冲音频但保留画面。后续单选合并 42 项定向测试通过，包含设置选择、原保存值保留及音量策略在下一控制器生效的回归测试，以及设置分组和资源翻译检查。
