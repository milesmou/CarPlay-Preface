# 星瑞 E02 方控与音量

设置页默认进入“连接”，无“概览”。媒体和导航音量位于“音频”，导航播报时方控调节开关位于“实验性”。

## 已实现的通用路径

- CarPlay 前台接收 Android 标准播放／暂停、上／下一曲按键，按下一次发送一次，重复按下和释放不重复发送；通话及无会话时保留车机处理。车载蓝牙音频模式由原车 AVRCP 控制音乐，前台不再重复转发。
- Android MediaSession 明确声明媒体按键及播放控制能力，并指定媒体音频用途。
- 媒体／导航输出比例分别保存，初始值均为 50%，范围 0–100%，0 为静音；已有保存值继续使用。保存后立即更新现有播放器，也适用于下次连接。音频焦点压低／静音／恢复媒体时乘以原有比例，不覆盖用户音量。
- 导航方控开关开启后，CarPlay 前台可处理标准音量键；后台使用现有无障碍按键服务。仅在导航实际播放期间处理，Siri 和通话优先。导航与媒体共用系统音量或采用自动路由时，只改变导航 AudioTrack 的输出比例；已明确指定且可用的独立系统音频流仍沿用系统音量调节。
- 导航结束后新按键交回原车，已接管的按键仍成对处理。应用不会默认选用其他车型的私有导航流编号。

输出比例是应用内增益，车机系统音量仍影响最终响度；不能用它让静音的车机扬声器出声。

## 固件 327 的原厂接口

已分析用户提供的星瑞固件，确认 `IHU519G / FS11A1 / Android 9 / 构建 327` 使用原厂媒体广播分发切歌和播放／暂停，媒体流为 3，导航流为 12。本仓库已为该固件接入广播并设置默认音频流；原厂直接处理的音量键继续交给车机。
完整编号、事件链路和证据见 [固件分析](PREFACE_FIRMWARE_327.md)。已有用户音频路由设置不覆盖，其他型号或构建号仍使用通用路径。静态分析不代表已经完成实车测试。

## 其他 E02 固件的待确认项

仓库保留的 `com.geely.inputservice` 绑定针对上游验证的 OneOS 车机，不构成星瑞 E02 原厂方控支持证据。E02 固件是否向第三方应用发送标准媒体／音量 KeyEvent、是否需要 ECARX AdapterAPI，以及原厂导航和媒体的音量分组，都需要星瑞真车验证。

请提供真车 ADB 连接，或该固件的 SDK／适配源码／系统媒体与输入组件及按键日志。应在停车状态记录固件信息、播放／暂停／上／下一曲／音量加减的事件，以及导航播报和音乐播放时的 `dumpsys audio`、`dumpsys media_session`。不要用其他车型编号直接替代，也不要仅凭模拟器测试宣称实车适配完成。

同为 E02 的其他车型也有专有按键分发案例，仅作为采集方向参考，不复制其映射：[E02 S70 原始按键研究](https://github.com/ardentlab/ecarx-e02-sideload/blob/main/docs/steering-button-remap.md)。
