# 星瑞 E02 兼容性与排查

本仓库仅面向 **2023 款吉利星瑞 1.5T（E02）车机，无飞屏功能**，所有默认配置直接使用星瑞方案，不以车型或固件识别作为启用门槛。静态固件分析、构建和单元测试分别记录，不能代替实车验证。

## 已有依据

用户提供固件为 IHU519G／FS11A1、Android 9／API 28、构建 327。媒体流 3、导航流 12 和原厂媒体键广播链路有静态证据，详见 [固件索引](PREFACE_FIRMWARE_REFERENCE.md) 与 [方控、音频分析](PREFACE_FIRMWARE_327.md)。不同 E02 固件仍需比对接口及实际运行结果。

OneOS 吉利／领克输入服务、FCE 仪表写入、哈曼全屏模式及电动车状态上报均已移除。地图在应用窗口中使用通用布局，不向比亚迪仪表、FCE MCU 或其他车型服务发送数据。

## 设置与默认行为

- 设置默认进入“连接”，通过分类栏切换，不提供概览、语言或车型选择。
- 媒体／导航流默认 3／12，音量由车机系统控制，导航混音只调整本应用音乐。保存过的自动路由和自定义值继续优先。
- 切歌广播、MediaSession 与前台窗口共用去重逻辑。通话和车载蓝牙音频模式保留原车优先处理。
- Siri 默认使用语音通信麦克风源，创建或初始化失败时尝试语音识别源；实际收音、回声和原厂私有语音键唤醒需要实车验证。
- 需要权限、ADB、特定 Android API 或会话状态的功能仍检查接口可用性。实验性功能集中在“实验性”菜单，按页面说明应用或重新连接。

## 排查顺序

1. 有线连接先确认数据线、数据端口及 USB 授权；无线先确认 iPhone 能手动加入同一热点。
2. 音频异常先确认媒体／导航路由及原车系统音量，车载蓝牙音频模式的音量由原车控制。
3. 方控异常记录原厂按键是否发出标准广播、CarPlay 是否在前台或拥有媒体焦点，以及通话／蓝牙模式状态。
4. 在“诊断”中保存报告，再向 [当前仓库](https://github.com/milesmou/CarPlay-Preface/issues) 反馈应用、固件、iOS 版本和复现步骤。

## 当前限制

旧包已有部分实车连接和切歌记录，见 [构建 100](CONNECTION_REPORT_2026-10-20_BUILD100_AUDIO.md)；当前统一包名版本尚未完成完整实车验收。USB 端口、无线自动加入、后台方控、导航独立音量、Siri 收音、通话抢占、地图和长时间连接均需实车测试。Android 模拟器能验证安装与界面，不能验证车机私有接口或真实声学效果。

无线提供临时热点和手动车机热点二选一，默认临时热点；不提供 Wi-Fi Direct 与同一局域网模式。临时热点使用 Android 公共 API，由系统决定频段和信道；手动模式使用用户已开启的车机热点及保存的匹配凭据，选择手动模式后尝试开启系统保存的热点，不修改配置或自动关闭；已有 CarPlay 会话时不操作开关。无法读取信道时保留自动值，不猜测信道；接口不明确或存在多个候选时拒绝随意选择。系统定位、权限、热点接口、iPhone 自动加入与蓝牙配对仍需实车验证。

桌面实时地图嵌入示例 `home`／`maphost` 要求 Android 11／API 30，不适用于当前提供的 API 28 固件；应用内地图仍保留。
