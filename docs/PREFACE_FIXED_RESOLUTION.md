# 星瑞固定 CarPlay 分辨率

2026-10-15 用户明确要求按“隐藏导航栏”选项严格锁定协商像素，并停用会改变像素的调节：

| 隐藏导航栏 | CarPlay 协商分辨率 |
| --- | --- |
| 勾选 | 1920×720 |
| 不勾选 | 1760×720 |

两个尺寸均为横屏像素，不是 dp。设置界面继续按实际可用窗口和密度布局。

## 应用行为

- `CarPlayHostActivity.nativeCarPlaySize()` 统一选择固定尺寸；实际 View 测量、窗口历史最大值、系统状态栏临时变化均不作为协商分辨率来源。无线与 USB 共用该配置。
- 移除设置页和会话内设置的分辨率百分比入口，不再读取旧分辨率百分比及旧 UI 画布缩放值来生成配置，不迁移或清除用户的旧数据。配置直接使用固定尺寸，避免旧备份值重新改变协商像素。
- 当前“CarPlay 尺寸”使用 `widthPhysicalMm` 调整图标、文字物理尺寸，保留此功能；它不改变固定像素。帧率、安全区域、程序栏位置和画面调整也保留。
- 窗口增长或缩小仅通过已有 `CarPlayVideoLayout` 调整本地显示与触摸坐标，不关闭控制器、重建热点或重新协商。真实屏幕旋转的原有处理仍保留。
- 导航栏选择引起的分辨率变化在下次连接生效。主设置页保存后显示“立即重连”提示；返回正在运行的会话不会仅因系统栏设置变化重建连接。会话内设置沿用明确的保存并重连按钮。
- 物理尺寸计算使用固定 1920×720 屏幕作为参考，不随临时窗口历史最大值变化；实际选择 1760 宽时按可用宽度计算。
- 新诊断报告显示两档固定分辨率选择及实际协商尺寸，不再将旧分辨率百分比描述成生效配置。

## 与报告的关系

[构建 65 报告](CONNECTION_REPORT_2026-10-15_BUILD65.md) 的首次临时热点会话在窗口从 1760×720 恢复为 1920×720 时主动重建连接，随后创建热点失败。本次修改消除窗口尺寸增长触发的重建路径；尚未取得新包实车结果，不能称临时热点稳定性已验证或热点创建错误已修复。

末尾手动热点断线后清理等待至少 16 秒、原厂媒体 API 未就绪以及 USB 无 AirPlay 接入均为独立待解决问题，本次不修改这些流程。

## 验证范围

48 项定向测试通过：固定像素与旧缩放值 5 项、窗口与会话生命周期 34 项、相关设置保存／取消／主动重连 6 项、设置截图 2 项、翻译完整性 1 项。完整和紧凑设置截图已目视核对，固定为 1920×720 横屏、字体比例 1.5；紧凑场景使用更高密度，图片位于本地忽略目录 `agent_docs/screenshots/fixed-resolution/`。

首次扩大到整个 `CarPlayHostSettingsTest` 时，7 项既有测试引用当前源码及修改前 HEAD 中均不存在的 `hotspotCredentialsView` 或 `vpnReady` 字段而失败；原始结果留在 `agent_docs/test-results/fixed-resolution-initial/`。这些旧热点／VPN 测试不属于本次分辨率行为验证，不恢复已删除的 VPN 或旧界面字段。另一本次新增描述引起的开关内容描述定位失败已修正，并重新验证相关测试。
