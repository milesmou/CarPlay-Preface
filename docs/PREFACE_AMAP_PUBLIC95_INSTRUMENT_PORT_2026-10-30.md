## 用户选择 9.5 移植方案后的继续研究

用户已明确选择向公众版 9.5 移植仪表，并确认没有其他匹配插件，继续只用现有资料和 327 固件。本阶段完成了可重复的只读分析工具和以下接口／配置复核；**尚未实现新的仪表渲染器，也未生成修改 APK**。

### 已缩小的目标范围

历史成功会话的原始日志 `APLog_2026_1029_164734__24/main_log_2__2026_1029_175218` 第 175194、175206、175208 行，记录原厂进程在 17:51:42 加载 `InstrumentPannelLarge`，其中实际库加载返回 1。这是该库进入成功会话的证据，不证明加载即完成准备，也不证明其他插件在所有场景都无用。当前研究先集中于 Large 窗口。

327 的 FS11A1 适配返回通道 `C04010181178`，该通道的功能配置将 `isStartupMultiScreen` 从基础值 0 覆盖为 7。单独的 `C04010181178_MultipleScreen.json` 则明确提供：

| 项目 | 327 的 E02 Large 窗口 | 公众版 9.5 默认 Large 窗口 |
| --- | --- | --- |
| WindowId | 1001 | 1001 |
| Surface 像素 | 1920×720 | 1024×524 |
| SurfaceRenderType | 1 | 0 |
| IsSeparateRender | 1 | 0 |
| CreateSurfaceWhenInit | 1 | 默认文件未显式设置 |
| 当前所选模式附加 UI | 巡航／引导均为 `IsUiVisiable=0`，UI 宽高为 0 | 首模式附加 UI 开启 |

上表是两个固定文件的静态配置，不是实际车机当前 Display、Surface 尺寸或物理仪表分辨率的读取结果；不得据此创建模拟屏幕或将中控截图当作仪表验收。9.5 文件还包含其他预置模式，本次不新增其他车型适配。

原厂插件并非只有图标资源：其二进制注册 `CGFrameSimulation::setRenderEndCallback`（327 插件虚拟地址 `0x3c3ec` 至 `0x3c3f8`），退出时解除（`0x428c0` 至 `0x428c8`）；渲染结束回调 `0x3dfd8` 还经旧任务队列转回处理线程。插件中另有真实扩展渲染状态通知调用 `GAI_ExScreenRenderStatusNotify`（`0x2c5f4`、`0x2c6b0`）。本轮未将这些不同位置未经完整追踪地等同为同一个首帧分支。

因此，即使关闭附加 UI，也不能用空库或“启动返回 true”替代插件负责的地图与渲染生命周期。9.5 的插件加载器本身也不把启动入口返回值作为实际首帧验收。

### 9.5 自带 TBT 模块的候选入口

公众版 `libautonavi.so` 导出 `Startuptbt`（`0xd2514c`）和 `Exittbt`（`0xd25244`），同时带有本版 `libcmb_TbtPackage.so`。启动入口使用传入窗口的 `getPackageMgr()` 加载 `TbtPackage`，不是可以随意当成无参数函数调用的通用服务；本轮没有调用它或构造其 C++ 对象。

这给后续重建提供了与 9.5 同版的资源／加载线索，但还不能直接替代星瑞插件：

- `Startuptbt` 末尾固定返回 1，没有把 `loadPackage` 的实际渲染结果作为返回值，不能拿它当 READY。
- 此入口的函数体没有补齐旧 Large 插件的地图渲染和扩展首帧通知链；单独运行一个 TBT UI 包不能证明会产生原车需要的 116。
- `CGPackage::startupInUI` 将回调投递到窗口线程；`exitInUI` 的队列和等待行为也需保留。把旧任务类型改名或将异步回调当同步执行，会引入退出与窗口销毁风险。

固定输入对应 `libGFrame.so` GNU Build ID 为 `4771f6aa70ef0f19413514db07cd726a20b03330`，`libautonavi.so` 为 `d99d7b71c32fc84fc612dc58f9ccb3084320b101`。这些偏移只适用于已经核对的文件，不是跨版本 SDK 契约。

### 可重复分析与剩余工作

新增 [只读分析脚本](../scripts/amap95_instrument_analysis.py)，在仓库根目录执行：

```powershell
python scripts/amap95_instrument_analysis.py
```

脚本先核对两份 APK 的固定 SHA-256，再读取 ELF 依赖／符号和 Large 专用窗口字段，输出本地忽略目录的 `renderer-contract.json`；不读取或导出含授权配置的 `FuncConfig`，不修改、构建、签名或安装 APK。输出始终明确 `portReady=false`，命令成功只表示报告生成。

已用两份固定 APK 实际生成报告；六项 Python 定向检查通过，覆盖必需／可选符号、架构及截断输入、哈希拒绝、未解析容器、重复 ZIP 条目和目标字段筛选。未执行 CarPlay 全量测试或 APK 打包。

## 本次继续：真实回调桥接源码与创建阻塞

本阶段新增自行编写的 [原生回调桥接](../amap95-instrument/README.md)，依据固定 9.5 的 `IMapServiceObserver` 消费端，完成两项析构入口及七项设备／Surface／绘制通知的顺序和标量参数适配。对象只转交原始事件；不推断 READY，不发送准备协议，也不实例化任何厂商 C++ 地图参数对象。

桥接固定会话和实际非主屏 EGL 设备身份，在设备／Surface 销毁时使当前租约失效，阻止同一设备 ID 重用时旧回调进入新会话；主动退出会等待正在执行的本对象回调。SDK 注册、移除和对象销毁仍须遵循接入顺序：先失效，再在 SDK 回调外注销，等注销返回后释放。固定库的观察者遍历与移除共用锁，不能从该锁内直接注销。这里只完成桥接组件，没有接通实际地图视图的创建。

### 已排除的误接入口

## 本次继续：观察者生命周期与复现流程

已在 [原生源码目录](../amap95-instrument/README.md) 补齐 `PinnedHslApi` 与 `ObserverSession`，使已确认的观察者接口具备绑定、注册前检查、注册后复核、当前会话转交、失败回滚和注销释放的完整流程。**这只是观察者流程，整个仪表移植仍未完成**；没有在高德进程内执行厂商接口，没有生成修改 APK。

生产绑定只接受已加载的固定 arm64 `libhsl.so`：使用 `RTLD_NOLOAD`，核对映射内 ELF 架构、GNU Build ID 及七个函数和一个导出单例变量所属映像。不会主动初始化 SDK、加载旧库或创建单例。脚本另外核对公众 APK 的固定 SHA-256，并从该 APK 记录绑定函数哈希；Build ID 本身不作为完整性签名。

窗口创建者将来须提供真实地图引擎 ID，并在窗口生命周期线程上保持地图有效。源码通过 `GetMapViewHandle`、本版视图 getter 和 `GetWindowId` 反查，要求实际地图一致、EGL 设备非主屏且窗口为 1001。固定 RTTI 数据确认 `MapViewBaseImpl` 的 `MapViewBase` 为偏移 0 的主基类；源码只调用已核对的 getter，不自行读取这些对象的内部字段。没有地图时返回 `EXISTING_MAP_UNAVAILABLE`，身份不符时返回 `MAP_WINDOW_IDENTITY_MISMATCH`。

注册期间先保持 Pending，注册后再次核对对象身份，发布会话句柄后才转交新事件。注册中销毁 Surface 或身份变化时撤销本次注册；不会重放此前绘制事件。退出先失效并等待回调，回调外注销后才释放。处于任何本仓库观察者的 SDK 回调中时，关闭操作只失效并返回 Deferred，保留句柄等待窗口线程稍后注销，避免重入 SDK 的观察者锁；保留其他观察者。所有者仍必须控制地图／上下文寿命和串行关闭，库引用不代替地图对象的所有权。

### 进一步核对的创建链

- `Context::InitModule` 在地图分支调用视图服务时传入默认参数，没有从这个入口获得可直接使用的 E02 专用参数构造器。
- `InitMapView` 的 `0xc13004` 至 `0xc13024` 在调用虚表 `0x48` 时明确将第一个标量置 0；下层 `CreatMapViewBase` 继续把该选择值传给 `CreateAndroidDisplay`，再用于 `GAI_MapSurfaceViewStatusGet`。不能以传入另一个引擎 ID 就宣称已切换到仪表 Surface。
- `GetMapEngineId` 先查表，稳定映射中缺失窗口会返回 -1；后半段还保留树插入实现。不能把这段静态插入分支描述为正常查询必然新增映射。本轮注册源码使用已知地图反查窗口，没有调用这条路径。
- `SetMapRenderStatus` 在固定 9.5 中更新内部状态表；方法自身没有补齐真实绘制或成功准备协议。没有调用它来制造准备状态。

原厂 Large 中尚需继续还原的成功路径，与已确认的两处错误状态 2、启动 Logo 结束任务分别保留。本轮未找到可直接接成 E02 渲染器的同版完整入口，没有因 TBT 导出存在就加载占位插件，也未据此判定所有重建路线均不可行。
